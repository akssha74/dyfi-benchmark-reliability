\title[A USGS DYFI benchmark for machine-learning evaluation]{A versioned,
leakage-audited USGS \emph{Did You Feel It?} benchmark for machine-learning
evaluation of severe felt intensity}

\author*[1]{\fnm{Akshay} \sur{Sharma}}\email{akssha74@gmail.com}

\author[1]{\fnm{Lalji} \sur{Prasad}}\email{lalji.research@gmail.com}

\affil*[1]{\orgdiv{Department of Computer Science and Engineering},
\orgname{SAGE University}, \orgaddress{\city{Indore}, \postcode{452020},
\state{Madhya Pradesh}, \country{India}}}

\abstract{Reliable comparison of models that estimate earthquake felt intensity
requires a stable reference dataset and evaluation rules that prevent related
events from crossing data splits. We introduce version~1 of a single-source USGS
``Did You Feel It?'' (DYFI) benchmark for retrospective prediction of severe
felt intensity (event-maximum community decimal intensity $\geq6$) from
earthquake source metadata. The resource combines a frozen dataset, a
six-category leakage audit, internally specified space--time sequence grouping,
outcome-independent analysis roles, endpoint sensitivity analysis, fixed
baselines, calibration-aware scoring, Brier-score sequence-cluster bootstrap uncertainty,
and a protected temporal evaluation. The frozen $M\geq5$ snapshot contains
7{,}520 records, 2{,}362 eligible events, and a 430-event temporal holdout. The
cross-validation comparison yielded small differences favoring sequence-grouped
over random folds (sequence minus random: Brier $-0.006$; area under the
receiver-operating-characteristic curve [AUROC] $+0.012$). Because the executed
analysis retained only point estimates for this contrast, we interpret it
descriptively. All learned baselines outperformed the no-skill reference, but
the paired 95\% interval between the two lowest-Brier models included zero;
therefore, we identify no winning model. The
benchmark provides a versioned, leakage-audited reference for future methods,
and every reported value can be reconstructed exactly from the frozen analysis
files.}

\keywords{Did You Feel It?, macroseismology, machine learning, benchmark
resource, sequence-grouped cross-validation, reproducibility}

\section{Introduction}\label{sec:intro}

The U.S. Geological Survey ``Did You Feel It?'' (DYFI) system converts
crowd-sourced felt reports into a numeric community-decimal intensity (CDI) for
each earthquake, providing a dense, decades-long record of observed shaking that
complements sparse instrumental networks~\citep{wald1999dyfi,atkinson2007dyfi,
wald2012dyfi,quitoriano2020dyfi}. Because the felt-intensity outcome of an event
is only realised after responses accumulate, a natural retrospective question is
how well the \emph{severe} outcome of an event---an event-maximum intensity in
the damaging range ($\mathrm{maxCDI}\geq 6$)---can be anticipated from
outcome-blind source metadata in the frozen catalogue snapshot (magnitude,
depth, location, origin time). These are preferred catalogue values at the
snapshot instant, not guaranteed first-alert or real-time values. To protect the temporal holdout, however, the
primary models use only magnitude and depth; location and origin time appear
only in restricted sensitivity analyses. This defines a descriptive,
retrospective target quantity,
useful for characterising how much of the severe-shaking signal is carried by
catalogue parameters alone, and it is distinct from any real-time,
operational, or causal claim.

A recurring methodological problem undermines the machine-learning literature on
this and adjacent tasks. Models are trained and evaluated on datasets assembled
ad hoc from the earthquake catalogue and split either at the record level or by a
single random train/test partition. Random splitting ignores the dependence
structure of seismicity: aftershocks of a mainshock share source parameters and
overlapping felt fields, so a random split can place near-duplicate events on
both sides of the partition and inflate apparent skill---a textbook form of data
leakage~\citep{kaufman2012leakage} that grouped or blocked cross-validation is
designed to remove~\citep{roberts2017cv}. Recent macroseismic-intensity studies
illustrate the pattern: models are fit on single-system instrumental or DYFI
data under random or stratified partitions, with no released, leakage-audited,
event-grouped evaluation resource that a later user could reuse without
reconstructing a contaminated split~\citep{patelli2026macroseismic,
mori2025explainable}. The consequence is that reported numbers are hard to
reproduce and easy to over-read.

\subsection{Contributions}\label{sec:contrib}

We address the reproducibility and leakage gap by introducing a versioned
benchmark resource centered on a reusable, leakage-safe evaluation contract.
Concretely, the resource provides:

\begin{enumerate}
\item \textbf{A single-source, version-frozen DYFI benchmark} for the exact task
``outcome-blind source metadata $\rightarrow$ later event-maximum
$\mathrm{maxCDI}\geq 6$'', frozen to one dated access instant so that any later
catalogue revision defines a new version rather than a silent overwrite
(Section~\ref{sec:data}).
\item \textbf{An executable six-category leakage audit} that rejects direct-label,
post-outcome-ascertainment, identifier-proxy, and downstream-product features,
and rejects cross-role sequence straddles and temporal-cutoff violations,
accepting \emph{only} the exact source-only feature set; it is exercised by 110
unit tests and rejects every deliberately contaminated test case
(Section~\ref{sec:leakage}).
\item \textbf{Internally specified, outcome-independent roles} built on order-stable
space--time sequence grouping and a temporal external holdout, so that split
membership never uses the label
(Section~\ref{sec:roles}).
\item \textbf{A fixed, non-selective baseline suite} with calibration-aware
proper scoring, Brier-score sequence-cluster bootstrap uncertainty, explicit handling of
ties and unavailable calibration estimates, and a single-use protected evaluation
(Sections~\ref{sec:metrics}--\ref{sec:oneshot}).
\item \textbf{A quantified leakage-inflation diagnostic} (naive random versus
sequence-grouped splitting) reported as a descriptive point estimate, together with a fully
reproducible release bundle and machine-readable verification record
(Section~\ref{sec:results}).
\end{enumerate}

The learned models establish reference performance for the benchmark. Their
comparisons do not identify a winner, and the study makes no cross-system,
real-time, lead-time, operational, or causal claim.

\subsection{Significance}\label{sec:significance}

The resource gives later studies a fixed, auditable contract instead of another
bespoke split. By combining a version-frozen macroseismic corpus, an executable
leakage audit, sequence-grouped roles, reference baselines, and exact
reconstruction, it turns citizen-reported felt intensity into a reusable
seismological testbed rather than proposing another standalone prediction model.

\section{Related work and novelty}\label{sec:related}

\paragraph{DYFI and macroseismic intensity.} The DYFI system and its CDI
construction, outlier handling, and post-event revision behaviour are documented
in the foundational and review literature~\citep{wald1999dyfi,atkinson2007dyfi,
wald2012dyfi,quitoriano2020dyfi}; these establish that CDI is an
after-the-event, response-driven quantity subject to ascertainment effects,
which is precisely why our protocol uses response count only to determine
eligibility and forbids it as a predictive feature (Section~\ref{sec:data}).
We reuse these provenance facts rather than re-deriving them.

\paragraph{Domain benchmark resources.} The INGe resource links Italian
macroseismic intensities to colocated strong-motion records for benchmarking
intensity--ground-motion relationships~\citep{oliveti2022inge}. It is a
domain-near resource precedent, but differs from the present event-level USGS
DYFI classification task, source-only feature boundary, leakage audit, and
protected temporal evaluation.
The 2026 USGS Western North America resource contains about 696{,}000
site-level macroseismic observations from about 5{,}600 earthquakes and is
predominantly DYFI~\citep{fathiansabet2026western}. It is a larger observational
resource, but does not define this event-maximum binary task, executable leakage
audit, or frozen temporal evaluation.
An adjacent event-level binary study used post-event LastQuake felt reports to
classify high- versus low-impact earthquakes and evaluated later 2022
events~\citep{lilienkamp2023feltreports}. Its crowdsourced predictors,
impact endpoint, and rapid-response objective differ from the source-only DYFI
benchmark and reusable evaluation contract developed here.

\paragraph{Macroseismic databases and citizen observations.} Event-specific
analysis in the 2019 Athens earthquake combined online felt reports with ground
motion and source modelling~\citep{kouskouna2021athens}. Crowdsourced
macroseismic observations have also been used to characterize geological
settings and spatial variations in shaking response~\citep{sarao2023crowdsourcing}.
Curated macroseismic
resources such as the Belgian traditional macroseismic database and
MACROSISDATA preserve historical intensity observations for transparent reuse
and later analysis~\citep{neefs2025btm,sira2025macrosisdata}. The present work
extends this seismological resource tradition from data preservation to a
versioned, executable contract for model evaluation.

\paragraph{Machine learning on felt/macroseismic intensity.} Recent studies
predict macroseismic intensity with random forests and gradient boosting from
instrumental or catalogue features~\citep{patelli2026macroseismic,
mori2025explainable}. Machine learning has also been applied to earthquake
alert-level classification using intensity-related features and to waveform
detection with openly released seismic datasets~\citep{ozupak2026alert,
ertuncay2025detection}. Those tasks use post-event intensity descriptors or
waveforms, rather than the source-only feature boundary studied here. Each
felt-intensity model application is evaluated under a
random or stratified partition and does not release a reusable, event-grouped,
leakage-audited benchmark; \citet{mori2025explainable} moreover predict from
instrumental ground-motion parameters rather than outcome-blind catalogue
metadata, and \citet{patelli2026macroseismic} evaluate a single-system
train/test split on seismometric inputs. Their concrete drawback for our purpose
is the evaluation contract: a random or stratified split does not remove
within-sequence near-duplicate contamination, and none ships an executable
leakage audit or a version-frozen resource that a third party can rerun.
Our protocol addresses that specific drawback with internally specified sequence-grouped
roles and an executable six-category audit.

\paragraph{DYFI-based intensity models and concurrent leakage-aware work.}
Closest to our exact data source, \citet{kumar2025dyfiindia} predict DYFI
community intensity from the same catalogue metadata (magnitude, depth, location)
with a random-forest regressor on Indian events under a single naive train/test
split (reported $R^2=0.829$); our resource does not fit a competing regressor but
instead supplies a versioned, digitally fingerprinted, event- and
sequence-grouped benchmark with an executable leakage audit and a protected
single-use evaluation, in place of
the naive split that setup uses. Concurrently, \citet{li2025llmworldmodels}
release a DYFI-grounded benchmark that simulates Modified Mercalli Intensity
(MMI) for
two earthquakes (2014 Napa and 2019 Ridgecrest) with large language models and
includes an explicit location-identifier leakage test; our resource differs in
task and construction---an outcome-blind source-metadata$\rightarrow$later-severe
binary classification over a decade-scale $M\geq5$ corpus with internally specified
sequence-grouped roles, rather than multimodal per-zip-code MMI simulation for two
events---so the two are complementary rather than duplicative.

\paragraph{Cross-validation for dependent data.} That grouped or blocked
cross-validation is the correct evaluation strategy for temporally, spatially,
or hierarchically structured data is established
practice~\citep{roberts2017cv,kaufman2012leakage}; we do not claim this as novel.

\paragraph{Novelty delta.} Conceding the above, the delta this resource supplies
that prior work does not is the \emph{released, versioned, hashed, single-source
DYFI benchmark} itself: an executable six-category audit covering forbidden
fields, proxy variables, and split contamination; an internally specified,
sequence-grouped role assignment with a
temporal external holdout, a documented severe endpoint with threshold and
threshold sensitivity, a fixed non-selective baseline suite with a no-skill
comparator, a calibration/uncertainty/tie contract, an exact-reproduction
guarantee, and a quantified naive-versus-grouped leakage-inflation headline. A
current-year search located no released resource occupying this exact
combination; novelty is stated as a concrete delta to located work, with no
first/only superlative asserted.

\section{Data, provenance, and outcome-boundary disclosure}\label{sec:data}

\paragraph{Source and single-instant pinning.} The corpus is derived entirely
from USGS DYFI and its parent ANSS Comprehensive Catalog (ComCat), retrieved
through the International Federation of Digital Seismograph Networks (FDSN)
event web service~\citep{usgs_dyfi_data,usgs_comcat}. The
acquisition envelope is outcome-independent: $M\geq5$, product type
\texttt{dyfi}, event type \texttt{earthquake}, starttime 2015-01-01 to endtime
2025-01-01. FDSN defines the end bound as inclusive; no frozen record occurs
at that boundary, so the realized snapshot spans 2015--2024. Results are ordered
by time. The preliminary count request and the final data request use this same
envelope. Because the catalogue evolves, the downloaded data were frozen at one
access instant (2026-09-01T06:33:30Z) and assigned a SHA-256 digital
fingerprint. A preliminary count changed from 7{,}575 to 7{,}576 during the
acquisition session, documenting one live-catalogue revision. The final
downloaded snapshot contained 7{,}520 DYFI records, and a count requested
50 seconds later in the same acquisition session also returned 7{,}520. Thus,
the one-record change belongs only to
the earlier preliminary checks; it is not a discrepancy in the frozen analysis
snapshot. Likewise, the 56-record difference between the last preliminary count
and the final 7{,}520-record snapshot is not an analysis exclusion: the
preliminary count had no paired payload, so its membership difference cannot be
decomposed and is retained only as catalogue-version provenance. The
near-contemporaneous final query and count agree exactly. The digital
fingerprint of the downloaded bytes, rather than a
preliminary count, defines this resource version. The frozen snapshot
contains 7{,}520 DYFI records (Table~\ref{tab:cohort}, Fig.~\ref{fig:cohort}).

\paragraph{Protocol chronology.} The file records an internal 2026-09-01 freeze
but was first publicly timestamped on 2026-09-19. We therefore describe it as an
internally frozen protocol, not an externally registered preregistration.

\paragraph{Retrospective eligibility and post-report ascertainment.} DYFI
intensity is an after-the-event quantity whose reliability grows with the number
of felt reports~\citep{quitoriano2020dyfi}. To keep the label meaningful we apply
a data-informed eligibility filter of at least ten responses per event. The
response count is used \emph{only} for eligibility and is explicitly forbidden as
a predictive feature, because it is a post-outcome ascertainment proxy; this
forbiddance is enforced by the leakage audit (family F2,
Section~\ref{sec:leakage}). Eligibility yields 2{,}362 events with severe
prevalence 0.298 (703 severe events). Of these, 2{,}360 events are assigned to
the internally specified analysis roles (Section~\ref{sec:roles}) and contain 702 severe
events; the remaining two are temporal-straddle exclusions, one of which is
severe. That single severe straddle event accounts for the difference between the
eligible cohort (703 severe) and the analysis-assigned set (702 severe), so
eligibility is not the same as analysis-role assignment (Table~\ref{tab:cohort}).

\paragraph{Endpoint.} The severe label is
$\mathrm{severe}=\mathbf{1}[\text{event-maximum } \mathrm{maxCDI}\geq 6.0]$
(intensity VI+). The primary threshold is 6.0, with reported sensitivity at
$\{5.5,6.0,6.5\}$ and a near-threshold band of $\pm0.5$
(Section~\ref{sec:endpoint-results}).

\paragraph{Outcome-boundary disclosure and held-out semantics.} Only corpus-level
outcome-blind counts and inherited aggregate feasibility statistics were exposed
before construction; no per-event label informed the endpoint, split, or
tuning choices, and role membership is assigned by an internally specified,
outcome-independent rule that never uses the label. We therefore describe the
external holdout as \emph{held out from model development with aggregate
feasibility previously known}, and we deliberately do \emph{not} call it
``untouched'' or ``confirmatory.'' Two event identifiers were prelisted for
quarantine because their aggregate counts had been seen during source
verification; neither identifier occurs in the frozen snapshot, so the rule is
non-operative in version~1 and excludes no record. The complete list of protocol decisions is reported in
Section~\ref{sec:repro-results}. No
respondent-level personally identifying information is redistributed; only
event-level source metadata, the severe label, the eligibility-only response
count, identifiers, and role assignments are released. Snapshot-level
provenance is supplied by the activated source-locator manifest and source
payload SHA-256; version~1 does not claim per-event product-version hashes. The
release bundle follows datasheet-for-datasets
documentation~\citep{gebru2021datasheets} and findable, accessible,
interoperable, and reusable (FAIR) data
principles~\citep{wilkinson2016fair}.

\section{Benchmark design}\label{sec:design}

\subsection{Feature sets and the six-category leakage audit}\label{sec:leakage}

The primary \emph{source-only} feature set contains magnitude and depth. It is
the only feature set evaluated on the temporal holdout. An
\emph{expanded-metadata} sensitivity analysis (baseline B3) additionally uses
latitude, longitude, and event year, so it is not evaluated where those
variables would disclose the holdout axis. The audit accepts only an approved
feature set with the expected fields in the expected order; any extra or unknown
field is rejected.

The executable audit enforces six leakage families. Field-level: F1 direct
label or its constituents; F2 post-outcome ascertainment or revision (including
the response count, eligibility-only); F3 identifier or source proxy; F4
downstream-product proxy. Split-level: F5 sequence cross-role straddle; F6
temporal-cutoff violation. An axis-proxy check additionally rejects origin year
under a temporal holdout and, when a geographic holdout is configured,
latitude/longitude/region. The latter audit branch is provided for reuse but was
not executed as an external evaluation in this study. This enforces the B3
restriction. The audit is useful independently of
model performance: it must reject every deliberately contaminated test case and
accept only the approved clean feature set. It is exercised by 110 unit tests
across four suites, all passing, and accepted the source-only feature set in the
frozen snapshot.

\subsection{Sequence grouping and outcome-independent roles}\label{sec:roles}

Events are grouped into seismic \emph{sequences} by order-stable single-link
space--time connected components (100~km, 30~days); the sequence, not the event,
is the unit of role assignment, so aftershocks cannot straddle roles. Roles are
assigned by an internally specified, outcome-independent rule (fixed assignment key,
temporal cutoff year 2023, development fraction 0.2, five cross-validation
folds); the rule provably never reads the label. The external holdout contains
events on or after 2023. The frozen internal protocol also named a secondary
leave-region-out geographic evaluation, but that branch was not executed and no
geographic role manifest is claimed. The reported geographic result instead
summarizes the temporal-holdout predictions by 10$^\circ$ cell
(Table~\ref{tab:slices}); Table~\ref{tab:exclusions} records this deviation.
Digital fingerprints of the completed temporal role assignments are published
so that third parties can verify them. The
partition is exhaustive and disjoint:
$1{,}573+357+430+2=2{,}362$ events, comprising 1{,}573 train, 357 development,
430 external temporal holdout, and 2 temporal-straddle exclusions
(Table~\ref{tab:cohort}, Fig.~\ref{fig:cohort}). Construction (train plus
development) is 1{,}930 events across 1{,}530 sequences; the holdout is 430
events across 354 sequences.

\subsection{Baseline suite and exclusions}\label{sec:baselines}

The fixed suite is B0 no-skill (constant prevalence), B1 magnitude-only logistic
regression, B2 source-only logistic regression, B3 expanded-metadata logistic
regression (used only in compatible sensitivity analyses), B4 random forest
(scikit-learn;
\citealp{pedregosa2011sklearn}), and B5 XGBoost~\citep{chen2016xgboost}. Each learned
baseline is tuned \emph{only} by the protocol-defined deterministic grouped
cross-validation on the construction corpus over a fixed grid, named before
evaluation, and carried unchanged to the protected holdout with frozen
best parameters. A machine-readable fit log enforces a maximum of 120 model
fits; the executed run used 91. Two comparators are excluded for protocol-defined,
reproducible reasons recorded in the protocol-decision table
(Section~\ref{sec:repro-results}): B3 is
not evaluated on the temporal holdout because its feature set carries origin year, a
temporal proxy; and the Atkinson--Wald (2007) DYFI intensity-prediction
equation~\citep{atkinson2007dyfi} is excluded because it cannot be applied to
the source-only feature set and tectonically heterogeneous population without
inventing a site-distance covariate, a per-event tectonic-regime assignment, and
a probability link.

\subsection{Metrics, calibration, uncertainty, and ranking}\label{sec:metrics}

The primary score is the Brier score~\citep{brier1950}; secondary scores are
log-loss, AUROC, and calibration intercept/slope~\citep{vancalster2019calibration}.
For numerical stability, log-loss clips predicted probabilities symmetrically
to $[10^{-15},1-10^{-15}]$ before taking logarithms.
Brier-score uncertainty is quantified by a sequence-cluster bootstrap
($n_{\text{boot}}=2000$, 95\% intervals) that resamples whole sequences rather
than events~\citep{field2007bootstrap}, with a minimum-valid-replicate rule.
Calibration and feasibility states are \emph{derived}, not hard-coded: a
constant-prevalence predictor has no identifiable calibration slope, so the
table reports that value as unavailable. Pairwise ranking uses a paired
sequence-cluster bootstrap Brier difference with an explicit tie probability;
the table reports whether each 95\% interval includes zero, together with a
tie-aware joint ordering (Section~\ref{sec:pairwise-results}). Because the
intervals use 2{,}000 Monte Carlo draws, near-zero endpoints are interpreted
cautiously rather than as stable ranking guarantees.
The protocol requested intervals for every metric; only Brier-based intervals
were retained, so other metrics are descriptive point estimates
(Table~\ref{tab:exclusions}).

\subsection{Protected evaluation and reproducibility}\label{sec:oneshot}

The protected temporal holdout is evaluated exactly once under an automated
single-use lock; a second evaluation is refused. After evaluation, two clean
reconstruction runs reproduced the recorded result fingerprint exactly, and the
frozen holdout predictions were recovered bit-for-bit from the released rows and
frozen best parameters (reported in Section~\ref{sec:repro-results}), under a
pinned scientific-Python
environment (NumPy, SciPy, scikit-learn, XGBoost;
\citealp{harris2020numpy,virtanen2020scipy,pedregosa2011sklearn,chen2016xgboost}).
All fits, exclusions, subsets, cutoffs, and pairwise comparisons are reported
regardless of outcome; the only permitted omissions are the protocol-defined
exclusions above.
Computation is local-only under a pinned environment.

\paragraph{Reproducible artwork and generative AI assistance.} All figures were
generated with Matplotlib~3.11.1 directly from the frozen analysis assets; no
manual image manipulation or AI-generated artwork was used. ChatGPT assisted
language editing, formatting, and syntax/consistency-oriented code review. It
did not generate data, model fits, statistical results, scientific
interpretations, or conclusions. The authors reviewed and verified every
assisted change and retain full responsibility for the manuscript and released
artifacts.

\subsection{Observed split-performance differences}\label{sec:leakage-results}

The resource's headline quantity is the optimism of naive random splitting
relative to the sequence-grouped protocol, measured for a fixed leakage
diagnostic---a random forest with 300 trees and unrestricted depth---under three
fold-assignment schemes on the construction corpus
(Table~\ref{tab:leakage}, Fig.~\ref{fig:leakage}).
This diagnostic is distinct from the tuned temporal-holdout baseline B4, whose
maximum depth is 3.
On this $M\geq5$
one-row-per-event universe the point estimates are small and slightly reversed:
the sequence-minus-random Brier difference is $-0.0059$ and the
random-minus-sequence AUROC difference is $-0.0124$, calculated from unrounded
scores. The sequence-grouped split therefore scores marginally \emph{better}
than the naive random split, not worse. The frozen internal protocol required
uncertainty reporting for this contrast but did not define a paired interval
estimator; the executed result contains point estimates only. We disclose this
unfulfilled element as a deviation and do not invent a post-hoc interval.
Accordingly, we report the contrast descriptively, not as
evidence of equivalence, a true zero effect, leakage, or a win. Its
plausible structural context is that 1{,}885 sequences are largely singleton
(1{,}530 in construction), leaving limited within-sequence near-duplicate
structure for a random split to leak. This does not prove a small true effect.
With one row per event,
event grouping imposes the same grouping constraint as random-event assignment,
but its deterministic fold allocation differs and therefore produces different
scores. It is reported as an intermediate control. The protocol remains reusable on datasets with more
multi-event sequences. The present result neither demonstrates practically
important leakage from random splitting nor establishes its absence.

\subsection{Pairwise ranking stability}\label{sec:pairwise-results}

Table~\ref{tab:pairwise} reports all ten pairwise Brier-score comparisons. Every
learned baseline performs better than the no-skill reference B0 (all four
intervals exclude zero). Among the learned models, the B2--B4 and B2--B5
comparisons have intervals that include zero. The remaining learned-model
intervals exclude zero, although the B4--B5 lower endpoint (0.0003) is
near the Monte Carlo boundary. In the joint
bootstrap ordering, B2 has the highest probability of being uniquely best
(0.613), followed by B5 (0.387), but the direct B2--B5 comparison remains
uncertain. These results therefore do not justify naming a winning model.

The frozen internal protocol allowed an ``equivalent'' verdict but did not specify a
positive numerical equivalence margin; its resolution floor was zero. We
therefore do not invent a post-hoc margin or label any models equivalent.
Instead, we report each point difference, 95\% interval, and
whether that interval includes zero. Table~\ref{tab:exclusions} records this
interpretive restriction, which changes no result.

\section{Discussion}\label{sec:discussion}

\paragraph{Benchmark utility.} The resource's utility does not rest on any model
outcome. It rests on four reusable properties, each demonstrated here: an
executable leakage audit that rejects seeded contamination and accepts only the
approved feature set; internally specified outcome-independent roles that a third party
can reproduce; calibrated, uncertainty-bearing baselines with a genuine no-skill
comparator; and exact reconstruction anchored by recorded digital
fingerprints and a single-use evaluation safeguard. A later study can evaluate a
new method against
this fixed contract without reconstructing a contaminated split, which is the
practical benefit the field currently lacks~\citep{patelli2026macroseismic,
mori2025explainable,roberts2017cv}.

\paragraph{Interpreting the split contrast.} The observed point estimate is
small and slightly reversed. In these folds the naive random split did not
inflate the diagnostic score, but the missing interval prevents an equivalence,
zero-effect, or ``little practical effect'' inference. The protocol remains
useful for datasets containing more multi-event sequences; this result neither
demonstrates leakage nor supports a win.

\paragraph{No winning model.} Every learned baseline separates from the no-skill
reference. However, the direct B2--B5 comparison between the two lowest-Brier
models is unresolved, as is B2--B4, so the results do not establish a decisive
winner. Consistent with the resource's scope, we claim no winning model and no
operational, real-time, lead-time, cross-system, or causal benefit.

\section{Limitations and threats to validity}\label{sec:limitations}

\paragraph{Outcome and catalogue limitations.} The endpoint is
magnitude-dominated, CDI remains sensitive to responder coverage, and magnitude
and depth are frozen preferred catalogue values rather than guaranteed
first-alert values. The ten-response rule mitigates ascertainment; response
count is used only for eligibility. B1 provides the simple magnitude comparator.

\paragraph{Unexecuted sensitivity and transport branches.} The geographic
values are temporal-holdout subgroups, not external transport evidence. The
protocol-defined geographic evaluation and aggregation-grid sensitivity were not
executed, and no alternative to the fixed 100-km/30-day sequence definition was
tested. Consequently, no geographic, aggregation, or sequence-definition
robustness claim is made.

\paragraph{Inference and held-out semantics.} The protocol-required split-contrast
uncertainty interval was not retained, so that result remains descriptive with
no equivalence or zero-effect inference. Non-Brier scores remain descriptive
point estimates. Pairwise intervals use 2{,}000 Monte
Carlo draws and near-zero endpoints are interpreted cautiously. The temporal
holdout was excluded from model development, but aggregate feasibility was
previously known; it is neither ``untouched'' nor confirmatory.

\paragraph{Public release.} Version~1 of the data, code, frozen results, and
reproduction instructions is available in a tagged public repository at
\url{https://github.com/akssha74/dyfi-benchmark-reliability}. The release retains
complete digital fingerprints so that later revisions remain distinguishable
from the version evaluated here.

\section{Conclusion}\label{sec:conclusion}

We release a versioned, digitally fingerprinted, single-source USGS DYFI
benchmark for retrospective severe felt-intensity prediction from outcome-blind
source metadata. The benchmark provides a reusable, leakage-audited evaluation
contract, reference baselines, and verification tools. On the frozen snapshot, the observed
split difference is small and slightly reversed, every learned baseline
separates from the no-skill reference, and comparisons among the lowest-Brier
models do not establish a winner. Every reported number reproduces exactly from
the frozen analysis files. The resource lets subsequent macroseismic-intensity work evaluate
against a fixed leakage-safe protocol, and remains reusable on denser-sequence
datasets containing more multi-event sequences.
